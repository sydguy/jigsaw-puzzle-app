# Navigation review — 5 October 2026

Scope: navigation increment, not full-screen M2 acceptance.

## Implementation and authority

SDK 55 uses expo-router/unstable-native-tabs with three explicit stable triggers. NativeTabs.hidden hides the whole bar during focused collection selection and phone Billing without dynamically removing triggers. Screen owns safe-area handling; native triggers disable automatic content insets. Native iPad placement/appearance is explicitly accepted by the owner. No EAS build or simulator was used.

The browser uses a separate navigation implementation to retain the mockup layout. It must not be presented as a native tab preview. Sources: [SDK 55 API](https://docs.expo.dev/versions/v55.0.0/sdk/router/native-tabs/) and installed expo-router 55.0.18 declarations.

## Screenshot comparison and refinement

References: design/mobile/mobile-homev1.png and design/tablet/tab-homev1.png for navigation. Compare content inside the device frames; exclude drawn hardware and OS status bars.

1. Captured the implemented phone Home and tablet Collection navigation with the isolated browser journey.
2. Compared icon silhouettes, selected lavender surface, three equal tab regions, labels and phone-versus-tablet alignment. Replaced Unicode glyphs with generated PNG artwork from graphics/.
3. Initial tablet bar was too tall. Reduced minimum item height from 68 to 48 on tablet and 56 on phone, enlarged tablet image boxes to 40, and aligned tablet labels alongside icons. Phone image boxes are 32; artwork uses contain sizing with no stretching.
4. Recaptured and inspected the revised phone/tablet screenshots. Navigation has the intended hierarchy, shape family and alignment without clipping. Exact pixel identity is not claimed: system font rendering, minimum touch targets and logical viewport sizes differ from the raster mockups.

Evidence (local, regenerated by tools/check-browser.cjs): .cache/browser-check/phone-home.png, phone-collection.png, android-collection.png, tablet-portrait.png, tablet-landscape.png. The test context has isolated data and leaves the owner's local collection unchanged.

Other screen content is still the first implementation increment and has not passed full visual matching. Home decoration, Create Puzzle's composite Add Image artwork, collection toolbars and remaining Settings states require their own build/capture/compare/refine cycles. Empty guest content and hidden AI controls are intentional approved differences from populated reference screenshots. Do not move those screens to accepted status on the strength of navigation captures.

Native layout, custom icon raster sizing/tint behavior, safe areas and accessibility require physical-device checks when native work resumes. JavaScript export/type checks do not satisfy that gate.
